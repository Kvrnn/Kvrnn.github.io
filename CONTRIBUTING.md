# Contributing

Thank you for helping improve the project. Start with its README, existing issues and repository-specific development instructions. For substantial changes, discuss the approach in an issue before implementation. Report vulnerabilities through SECURITY.md rather than a public issue.

## Issues

Describe the problem, affected version, environment, expected result and a minimal reproduction. Use synthetic data and remove credentials, personal information and internal infrastructure details. Search for an existing report before opening a duplicate.

## Pull requests

1. Create a focused branch from the repository's documented contribution base. Its default branch may be named differently from main.
2. Follow the project's installation and development instructions. Run its applicable build, formatting, lint, type and test checks. State which checks ran and any that could not run.
3. Explain the behavior change, compatibility impact and relevant issue. Add meaningful tests for behavior changes and update user documentation where needed.
4. Preserve license headers, attribution and third-party notices. Discuss new dependencies and their licenses. Keep generated artifacts consistent with the project's existing conventions.
5. Submit a focused PR and respond to review. Do not include unrelated changes, live secrets, customer data or unlicensed copied material. Disclose material AI assistance and verify the resulting code and its provenance yourself.

## Contribution rights

The affected repository's license and any applicable contributor agreement govern contributions. Submit only work you are authorized to contribute, including any required employer permission. This shared guide does not grant software usage rights or change an existing license.

Projects using separate personal and commercial licenses may require an additional contributor agreement before acceptance. Maintainers must publish that agreement and its acceptance process before accepting contributions that depend on additional commercial licensing rights. A PR checklist or sign-off alone does not establish those rights.

Follow CODE_OF_CONDUCT.md in project interactions. Community review and support are provided as maintainer availability permits.
